# 文章 app 產品頁與問卷（content-product）規格

狀態：已驗收（2026-11-04）

## 目標

網站介紹文章 app，並用一份問卷確認內容接案者與研究型創作者有沒有「出處查不到」的痛點、願意付多少。

## 範圍

- `/products` 改成兩個產品的入口頁。現有查核產品頁搬到 `/products/verify`。
- 新增文章 app 的產品頁 `/products/content` 與問卷 `/survey/content`。
- 現有問卷搬到 `/survey/verify`；`/survey` 永久轉址。
- 導覽列、部落格文章的問卷按鈕、部落格文章最後一行跟著改。
- 以上每一頁都有中文與英文（`/en/...`）。`preview.html` 涵蓋新頁。

術語照 `CONTEXT.md`：文章 app、買斷、維護合約、證據標記、文章包、網站外框、對應文章。

## 決策來源

唯一的決策來源是 2026-11-04 的共識（grilling 對話，暫存檔 `consensus.md`）。
「對話問題序號」欄的 Q 編號是那次對話的問題序號。共識沒有講到的事，起草時列為未決事項，2026-11-04 由使用者照助理建議定案（D31–D56）；票單起草時找到的缺口同日定案（D57–D61）。

## 可觀察的行為

每一條都是使用者在瀏覽器上看得到、或在資料庫裡查得到的結果。英文頁的規則見 B31。

### 入口頁 `/products`

- **B1**　`/products` 顯示兩個產品的入口頁。H1 是「交出去之前，先確定它站得住」。
- **B2**　入口頁有兩張靜態卡。卡片不放影片。
- **B3**　查核卡顯示：標題「AI 說『做完了』」、說明「交出去之前，找出錯在哪裡」、給誰「律師、工程師、稽核……」（「……」不照字面顯示，完整列舉由助理起草，見 D58）。圖片是 `report_clean.jpg`，圖上標「示意畫面 · AI 生成」（D63）。點卡片到 `/products/verify`。
- **B4**　內容卡顯示：標題「每一句都查得到出處」、說明「做的時候就留下證據，交出去不怕被查」、給誰「內容接案者、研究型創作者……」（同 B3，見 D58）。圖片是新的示意圖（不是占位圖，見 D56），圖上標「示意畫面 · AI 生成」。點卡片到 `/products/content`。
- **B5**　入口頁任何地方都沒有「治療」或「預防」字樣。
- **B6**　入口頁底部顯示「也接 Web 開發與專案設計 → 聯絡我們」，「聯絡我們」連到 `/contact`。

### 查核產品頁 `/products/verify`

- **B7**　`/products/verify` 顯示現有查核產品頁的全部內容（放大鏡開場、情境卡、按鈕），文字與圖片和搬家前相同。

### 文章 app 產品頁 `/products/content`

頁面依下列順序有五段。頁面沒有情境卡。頁面不寫產品名稱，用描述當標題。

- **B8**　第 1 段「開場示範」：H1 是「每一句都查得到出處」。下面是一段真實部落格文章的摘錄（中文見附錄 B，英文見附錄 C）。
- **B9**　在摘錄裡點任何一句（手機上輕觸），那一句旁邊展開它的證據：原文引句、限定條件、原始網址。限定條件一定和引句一起顯示。
- **B10**　示範用的引句與限定條件寫在網站自己的文案裡。文章包的格式不變。
- **B11**　第 2 段「為什麼平常做不到」：上排顯示「查資料 → 寫稿 → 配圖 → 排版 → 上線」五個工具，並說明每換一次工具，出處連結就斷一次。下排顯示「提問 → 研究 → 查核 → 大綱 → 製作 → 驗收 → 成品」是同一條線，出處一路跟著。
- **B12**　第 3 段「實際案例」：列出 `body.html` 有證據標記（`<sup class="cite" data-e="…">`）的文章，每一篇連到文章頁。清單由網站自動判斷，規則和 B30 相同。今天的結果：有 `solo-trust`、`ai-handover`；沒有 `shadow-ai`、`shadow-ai-en`。只列同一種語言的文章（D46）。某一種語言沒有帶證據標記的文章時，那一種語言的頁面整段不顯示（D59）。
- **B13**　第 4 段「怎麼付費」：顯示「一次買斷，永久使用；之後可選擇加購維護合約，取得更新與修正。沒有維護合約也能繼續用，只是拿不到更新。」並明寫：維護合約不含一對一技術支援；沒有維護合約，就拿不到任何更新，包括外部服務（AI API 等）改版造成的修正。
- **B14**　產品頁任何地方都不顯示金額。
- **B15**　第 5 段「階段說明」：顯示「這個產品還在打磨，還沒開放使用……」，下面的主要按鈕連到 `/survey/content`。

### 文章 app 問卷 `/survey/content`

完整題目與選項見附錄 A。

- **B16**　開場顯示一句標題、一句為什麼問，與三項承諾：約 6 分鐘；名字和聯絡方式只有我們看得到；回報是寄彙整報告，並在開放試用時優先通知。
- **B17**　問卷分五段：01 關於您、02 最近一次、03 現在的做法、04 付費、05 聯絡方式。題目與選項和附錄 A 相同。
- **B18**　第 02 段「交出去之後」選「有人問出處」或「有人指出錯誤」時，顯示追問「後來怎麼處理、付出什麼代價？」。選其他選項時，不顯示追問。
- **B19**　第 04 段一開始只顯示盲問「這樣的工具，一次買斷您願意付多少？」（US$___ · 不會付費 · 不知道）。揭曉的兩題一開始隱藏。
- **B20**　填完盲問、按「下一步」之後，揭曉的兩題才出現。出現之後，盲問那題鎖住，不能再改。盲問旁邊顯示小字：「看到價格之後就不能改了，這樣我們才知道您原本心裡的價格。」沒有 JavaScript 時，整段（盲問與揭曉兩題）一次顯示，不顯示這行小字（D32、D61）。
- **B21**　揭曉的第一題顯示：實際定價是買斷 US$150，含 3 個月維護合約，之後每 3 個月 US$30。選項：會買 · 會考慮 · 太貴 · 不需要。揭曉的第二題：維護合約到期，您會續嗎？選項：會 · 看當時的更新內容 · 不會。
- **B22**　問卷的金額一律用 US$。中文頁和英文頁一樣。
- **B23**　第 05 段只有名字、聯絡方式、願不願意之後實際試用並給回饋。沒有公司或品牌欄。整份問卷沒有圖片或影片的題目。
- **B24**　必填：角色、團隊人數、每月篇數、付費三題（盲問與揭曉兩題）、名字、聯絡方式。開放題選填。必填題沒填就送不出去，頁面指出是哪一題。
- **B25**　按一次送出就送出整份。送出成功後，資料庫的新表多一列。這一列的選擇題存中文字，`lang` 欄記 `zh` 或 `en`。`survey` 表沒有新增列。

### 查核問卷 `/survey/verify` 與轉址

- **B26**　`/survey/verify` 顯示現有查核問卷，`?pick=` 預選照舊。送出的答案照舊存進 `survey` 表。`survey` 表裡已經收到的答案不變。
- **B27**　用 GET 開 `/survey` 回應 301，轉到 `/survey/verify`。網址帶 query string（例如 `?pick=<值>`）時，轉址後的網址原樣帶同一段 query string（D60）。`/en/survey` 同樣 301 到 `/en/survey/verify`。POST 到 `/survey`、`/en/survey` 不轉址：答案照舊存進 `survey` 表，行為和搬家前一樣（D55）。

### 導覽列與部落格

- **B28**　每一頁的導覽列都沒有「填寫問卷」。
- **B29**　部落格文章 `.bl-invite` 提問框裡的問卷按鈕，中文文章連到 `/survey/verify`，英文文章連到 `/en/survey/verify`。
- **B30**　`body.html` 有至少一個證據標記的文章，文章最後多一行「這篇文章由麒麟魚的內容工具製作，每一句都查得到出處 →」，連到 `/products/content`（英文文章用英文文案，連到 `/en/products/content`）。沒有證據標記的文章沒有這一行。網站自己判斷，文章包與 CompanyofOne 不需要改。今天的結果：`solo-trust`、`ai-handover` 有；`shadow-ai`、`shadow-ai-en` 沒有。

### 中英文與預覽

- **B31**　B1–B30 的每一頁在 `/en/...` 都有英文頁，和中文頁同時上線。英文頁的結構與行為和中文頁相同；英文頁的連結都指向 `/en/...`。語言切換鍵在兩語之間互相指向同一頁。
- **B32**　`/survey` 改成轉址之後，`python tools/build_preview.py` 仍然跑得完，產生 `preview.html`。`preview.html` 可以打開 `/products`、`/products/verify`、`/products/content`、`/survey/verify`、`/survey/content`，中英文都有。
